# 启动优化测量 — 2026-10-09

环境：本机 Apple Silicon，合成 SQL；不读取业务数据。所有结果只代表这台电脑当时的负载与缓存状态。

## 改动

1. 编辑界面、样式和脚本从 .app 内直接加载，消除先加载临时占位页、再等待本地 HTTP 页面跳转的依赖。
2. 界面和引擎并行准备；引擎后台预热，准备期间可输入 SQL，首次检查请求可等待引擎，不刷新编辑区。
3. Flask 启动不再立即导入检查库；原有 SQLGlot/SQLFluff 规则全部保留。
4. 修复冻结应用的 `multiprocessing.freeze_support()` 初始化。旧版缺少此调用会使资源跟踪辅助进程误执行应用入口。依据 [PyInstaller 官方说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing)。
5. 验证应用正常退出后不残留检查服务。

## 本地后端测量

`benchmark_startup.py` 启动冻结后的独立引擎，用单条合成 SQL 测量。每版 5 次；首次样本可能涉及文件/安全检查，不能当作受控冷启动实验。

| 指标（秒，中位数） | 原 v1.0.2 | 最终 v1.0.3 |
|---|---:|---:|
| 本地服务准备 | 0.3462 | 0.1776 |
| HTTP 页面可取 | 0.3495 | 0.1986 |
| 取页面后立即执行首次检查 | 0.0902 | 0.2661 |
| 启动到首次检查完成 | 0.4391 | 0.4670 |

新版将引擎初始化移到后台，因此早期首次检查仍可能等待；**没有证明首次检查总耗时更短**。主收益是界面不再依赖引擎启动与 HTTP 页面导航。旧版第一次独立引擎样本为 3.74 秒，新版第一次样本为 0.45 秒，但缓存和系统检查条件不同，不将这组差异当作保证。

## 原生界面测量

在仅记录时间、不记录 SQL 的专用测试包中，从 Swift 主程序开始计时：

| 最终版一次实测 | 秒 |
|---|---:|
| 窗口显示 | 0.5929 |
| 编辑界面加载完成 | 1.1403 |
| 本地服务准备 | 1.1116 |
| 完整检查引擎就绪 | 1.4387 |

旧版同次专用测试中，服务 1.43 秒已准备，但 HTTP 编辑界面直到 30.97 秒才完成导航。该单次异常说明页面导航也可能造成长时间等待；没有足够样本把 30.97 秒视为旧版一般速度。新版文件界面绕开这条 HTTP 导航路径。

上述时间不包含 macOS 启动应用主程序之前的签名、Gatekeeper/首次安全检查，也不保证不同电脑性能。正式交付包未编译时间记录功能，不生成启动测量文件或保存 SQL。
